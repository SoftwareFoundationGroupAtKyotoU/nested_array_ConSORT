# nested_array_ConSORT

An extension of [ConSORT](https://www.fos.kuis.kyoto-u.ac.jp/projects/consort/, https://github.com/mamizu-git/Extended_ConSORT) with support for nested arrays.

[日本語版 README はこちら](README.ja.md)

## Usage

All commands below should be run from the `myproject/` directory.

- Run ownership inference on a `.imp` file (results are output to `out_sat_ans.smt2`):

    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp
    ```

    - If you get a "busy" error:
    ```sh
    dune exec --build-dir="_tmp" myproject -- ./example/positive_example/init_10.imp
    ```

    - Refinement (assertion) checking only — use this if ownership checking has already been completed and you only wish to perform refinement type checking:
    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp -refinement
    ```

    - Fully annotated mode — use this when all matrix type annotations are provided in function definitions (expected to be faster than the standard mode):
    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp -full_annotated
    ```

    - Disable heuristics in ownership inference:
    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp -random_assignment
    ```

    - Automatic alias insertion (correctness of the inserted aliases is not guaranteed):
    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp -insert_alias
    ```

- Pretty-print the parsed AST of a program:

    ```sh
    dune exec myproject -- ./example/positive_example/init_10.imp -print_program
    ```

- Verify all `.imp` files in a specific directory:
    ```sh
    make run DIR=./example/...
    ```

- Pass additional options:
    ```sh
    make run DIR=./example/omit_alias OPTS="-insert_alias"
    ```

- Verify all `.imp` files under `positive_example/`, `negative_example/`, `much_time_example/`, and `omit_alias/`:
    ```sh
    make run_all
    ```

## Notes

- Several example programs are provided in `example/`. Feel free to try different files.
- To use Eldarica instead of hoice for refinement checking, replace the hoice invocation in `main` with:
  ```
  <path-to-eldarica> -hsmt ./experiment/out_chc.smt2 > experiment/chc_result
  ```
  For example:
  ```
  ~/Downloads/eldarica-2.2/eld -hsmt ./experiment/out_chc.smt2
  ```

## Building

### Dependencies

The tool is written in OCaml, and it is known to work with OCaml 4.14.1.
It also depends on the following OCaml libraries:

* zarith
* ppx_deriving
* ounit2
* seq
* unix
* stdlib-shims
* menhir

The following are additional dependencies that are used to solve the constraints generated by our tool.
Both must be on `$PATH`.

* [z3](https://github.com/Z3Prover/z3) (tested with 4.14.1)
* [hoice](https://github.com/hopv/hoice) (tested with 1.10.0)

#### Installing hoice

hoice requires Rust. Install Rust via [rustup](https://rustup.rs/) if you haven't already.

Note: hoice v1.10.0 does not compile with Rust 1.81+. Use Rust 1.78.0:

```sh
rustup install 1.78.0
rustup run 1.78.0 cargo install --git https://github.com/hopv/hoice --tag v1.10.0 --locked
```

This places the `hoice` binary in `~/.cargo/bin/`, which should be on your `$PATH` if Rust was installed via rustup.


### Compilation

We use `dune` for compilation.
The following command should build the executable `main`.
``` sh
cd myproject
mkdir -p experiment/own_result
dune build
```

Note: The `experiment/` directory is used to store intermediate files generated during verification. It must be created before running the tool.

To clean the object files and the executable, simply run:

```
dune clean
```
while you are in `myproject/`.

## Running

The simplest way to run the tool is to use `dune exec myproject` provided that `z3` and `hoice` are installed.
For example:

``` sh
dune exec myproject -- ./example/positive_example/init_10.imp
```
will check the absence of assertion failure in `init_10.imp`.
If you see `ownership: sat` and `refinement: sat`, it means that the ownership and refinement inference have succeeded, respectively.

### Options

| Flag | Purpose |
|---|---|
| `-refinement` | Refinement (assertion) checking only. Use if ownership checking has already been completed. |
| `-full_annotated` | Fully annotated mode. Use when all matrix type annotations are provided in function definitions. Expected to be faster. |
| `-random_assignment` | Disable heuristics in ownership type inference. |
| `-insert_alias` | Automatic alias insertion. Correctness of inserted aliases is not guaranteed. |
| `-print_program` | Pretty-print the parsed program AST. |
| `-unsat-core true/false` | Enable/disable unsat core analysis (default: true). |
